There is a potential issue with session handling in the current design. We are using one SQLAlchemy session per CR and processing multiple questions within that session. If any database operation (e.g., insert/commit in `store_results`) fails for a question, the session may enter a failed state. Without an explicit `session.rollback()`, the same session is reused for subsequent questions, which can lead to: - subsequent `add()` / `commit()` calls failing - queries behaving unpredictably - later questions not being processed correctly even though the loop continues This means the impact is not limited to a single question — it can affect all remaining questions in that CR. We should ensure that after any exception during question processing, we call `session.rollback()` before continuing. Suggested change in `main()`: ```python try: await process_question(session, question, cr_number, data_cache) total_stored += 1 except Exception as e: session.rollback() job_logger.error( f"[question_processing] [{cr_number}] question {question.question_id}: unhandled error - {e}" ) ``` Please confirm if this aligns with SQLAlchemy best practices and whether any additional safeguards are needed.
