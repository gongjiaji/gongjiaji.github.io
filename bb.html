I reviewed ds_command_logs.py again. Main issue before PROD: 1. store_data() currently checks duplicates row by row with one DB query per log. This will become a bottleneck in PROD for large batches. We should avoid N queries here. Either: - remove exact duplicate/new_insert counting and just bulk upsert + log total/unique_crs, or - batch-load existing composite keys and compare in memory. 2. Please confirm all datetime values are normalized to the same format/type before _assign_sequence_numbers(). If some are timezone-aware and some are naive, sorting can fail in PROD. Non-blocking improvements: 3. _create_log_entry() should return Dict[str, Any] | None, since it can return None. 4. In get_logs_graylog(), add contextual error logging around requests.post()/raise_for_status() with tower/chunk/from_index before re-raising. 5. Current duplicates/new_inserts stats are not fully accurate because they only detect duplicates already in DB, not duplicates inside the current batch. If we keep this logic, the log wording should be adjusted to avoid misleading numbers. Other than that, the overall exception handling and logging structure looks good.
